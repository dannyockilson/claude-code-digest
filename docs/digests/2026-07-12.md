# Claude Code Weekly Intelligence Digest

## This Week's Highlights

Seven Claude Code releases (v2.1.202–207) shipped critical stability fixes and UX improvements: auto mode now defaults on for Bedrock/Vertex/Foundry, background session stalls on macOS are resolved, and shell-injection hardening now rejects `${user_config.*}` in plugin hooks. The MCP TypeScript SDK shipped v2.0.0-beta.3 with breaking Content-Type validation changes and restored v1 compatibility for legacy servers. Community tooling exploded with multi-model orchestration layers, skill routers, and agent profile miners gaining significant traction.

## 🚨 Breaking Changes & Action Required

### anthropics/claude-code v2.1.207
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.207)

Auto mode now **enabled by default** on Bedrock/Vertex/Foundry (disable via settings if unwanted). Shell-injection hardening breaks plugin hooks using `${user_config.*}` in shell form—**migrate to exec form arrays immediately**. Also ships critical fixes: terminal freezing during long streaming responses, remote settings consent dialog bypass, and git worktree config pollution breaking go-git tools.

**Why it matters:** Auto mode default changes agentic behavior out-of-the-box; shell-injection fix may break existing plugin configurations requiring immediate code changes.

---

### anthropics/claude-code v2.1.206
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.206)

MCP server `request_timeout_ms` now properly respected (fixes blanket 60s timeouts); OAuth servers no longer require manual re-auth after token refresh. `/commit-push-pr` auto-allows `git push` to configured push remote, not just `origin`. Windows agents view fixed for keyboard input ignored on startup with `--resume`/`--continue`.

**Why it matters:** Timeout fixes prevent false-positive MCP server failures; OAuth fix eliminates manual token refresh interruptions in CI/CD workflows.

---

### anthropics/claude-code v2.1.205
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.205)

`--json-schema` now **validates schemas** and respects the `format` keyword—previously silently produced unstructured output. Auto mode blocks tampering with session transcripts and asks before executing `rm -rf` on unresolved variables.

**Why it matters:** JSON schema validation breaking change will surface previously hidden malformed schemas; auto mode safety prevents accidental data loss from incomplete variable resolution.

---

### anthropics/claude-code v2.1.204
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.204)

Critical bug fix: SessionStart hooks now correctly stream events in headless sessions—v2.1.204 regression caused remote workers to be prematurely idle-reaped mid-hook execution.

**Why it matters:** Headless/remote worker deployments were broken in v2.1.204; upgrade immediately if deploying background agents.

---

### anthropics/claude-code v2.1.203
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.203)

Fixed critical 15–20s background session stall on macOS (regression since v2.1.196) and stale daemon tokens permanently breaking background sessions. Subagents now inherit PATH/ANTHROPIC_BASE_URL correctly on Windows. Session resume instant even in repos with many git worktrees (was taking minutes + high memory).

**Why it matters:** macOS background session fix restores usability for local automation; worktree performance fix unblocks large monorepo workflows.

---

### anthropics/claude-code v2.1.202
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.202)

`/review <pr>` **reverted to single-pass** (faster); use `/code-review <level> <pr#>` for multi-agent reviews instead. Dynamic workflow size setting in `/config` lets you control agent count scaling (small/medium/large). Fixed Ctrl+R history search crashes and `/rename` session persistence.

**Why it matters:** Command behavior change for PR reviews; multi-agent review workflows must switch commands.

---

### modelcontextprotocol/typescript-sdk @modelcontextprotocol/node@2.0.0-beta.3
[Release Notes](https://github.com/modelcontextprotocol/typescript-sdk/releases/tag/%40modelcontextprotocol/node%402.0.0-beta.3)

**Breaking:** POSTs now properly parse `Content-Type` headers and reject non-`application/json` with 415 status—previously substring matching allowed bypasses like `text/plain; a=application/json`. New `isJsonContentType(header)` helper exported for custom transport authors.

**Why it matters:** Security hardening breaks lenient Content-Type handling; custom MCP servers must update header validation.

---

### modelcontextprotocol/typescript-sdk @modelcontextprotocol/hono@2.0.0-beta.3
[Release Notes](https://github.com/modelcontextprotocol/typescript-sdk/releases/tag/%40modelcontextprotocol/hono%402.0.0-beta.3)

**Breaking:** Strictly validates `Content-Type` headers—non-`application/json` requests return 415. Substring matching and case-variant bugs fixed. New `isJsonContentType(header)` helper exported for custom transport authors.

**Why it matters:** Same Content-Type hardening as @modelcontextprotocol/node; Hono-based MCP servers must update validation logic.

---

### modelcontextprotocol/typescript-sdk @modelcontextprotocol/core@2.0.0-beta.3
[Release Notes](https://github.com/modelcontextprotocol/typescript-sdk/releases/tag/%40modelcontextprotocol/core%402.0.0-beta.3)

**Breaking (but backwards-compatible):** Restores v1 parse tolerance for `CallToolResult.content`—legacy servers returning `structuredContent`-only results without `content` now default to `[]` instead of `INVALID_RESULT` errors. Strictness preserved for 2025+ wire schemas.

**Why it matters:** Unblocks years of deployed servers that worked with SDK v1; new servers still enforce strict content requirements.

---

### modelcontextprotocol/typescript-sdk @modelcontextprotocol/client@2.0.0-beta.3
[Release Notes](https://github.com/modelcontextprotocol/typescript-sdk/releases/tag/%40modelcontextprotocol/client%402.0.0-beta.3)

**Breaking:** SDK error classes now support `instanceof` across separately bundled copies via Symbol-based branding—affects gateway/host error handling patterns. Content-Type validation fixed to strict media-type parsing (rejects non-JSON POSTs with 415). CommonJS `validators/ajv` subpath fix resolves `ReferenceError: import_ajv is not defined`.

**Why it matters:** Error handling in multi-package deployments (gateways) must account for cross-bundle instanceof; Content-Type strictness matches @modelcontextprotocol/node.

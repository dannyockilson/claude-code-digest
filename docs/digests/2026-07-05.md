## 🚨 Breaking Changes & Action Required

### **Claude Code v2.1.200: Permission & Dialog Behavior Changes**
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.200)

**Breaking:** AskUserQuestion dialogs no longer auto-continue after idle timeout by default—requires explicit `/config` opt-in to restore old behavior. Default permission mode switched from "default" to "Manual" across CLI, VS Code, and JetBrains, requiring explicit approval for all tool calls unless you pass `--permission-mode manual` flag. Also fixes critical daemon crashes from stale locks, mid-turn stops after system sleep/wake, and subagent failures after rate limits.

**Why it matters:** Existing automation workflows may halt unexpectedly; review scripts and CI/CD pipelines for permission-mode assumptions.

---

### **Claude Code GitHub Actions v1.0 GA**
[Documentation](https://code.claude.com/docs/en/github-actions)

Beta users must migrate workflow syntax: replace `@beta` with `@v1`, rename `direct_prompt` → `prompt`, migrate `max_turns`/`model`/`custom_instructions` to unified `claude_args` flag format. Mode detection now automatic (no manual config needed). New setup via `/install-github-app` CLI command (v2.1.187+) simplifies integration.

**Why it matters:** Beta workflows will break on next run; update immediately to avoid CI failures. Track GitHub Actions minutes *plus* Claude API token costs.

---

### **MCP Python SDK v2.0.0b1: Architectural Overhaul**
[Release Notes](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v2.0.0b1)

First beta with full 2026-07-28 spec support. `MCPServer` replaces `FastMCP`, new stateless `Client(target, mode='auto')` auto-negotiates protocol versions, dispatcher/runner pipeline replaces v1 session internals. Multi-round-trip requests (tools can ask for input mid-call), RFC 6570 URI templates, header-based routing (SEP-2243), enterprise auth (RFC 8693), and OpenTelemetry tracing now included by default. Passes official conformance suite (except tasks module).

**Why it matters:** v1 code won't work with v2 servers; plan migration path before production deployments.

---

### **MCP TypeScript SDK v2.0.0-beta.1: Split Package Architecture**
[Release Notes](https://github.com/modelcontextprotocol/typescript-sdk/releases/tag/v2.0.0-beta.1)

Monolithic SDK split into separate `@modelcontextprotocol/server` and `@modelcontextprotocol/client` packages with optional adapters (Express/Hono/Fastify/Node). No longer Zod-dependent—supports Standard Schema (Zod v4, ArkType, Valibot) or plain JSON Schema. HTTP-first design with `serveStdio()` for local, `createMcpHandler()` for web-standard Request/Response. Automated migration via `npx @modelcontextprotocol/codemod@beta v1-to-v2 .`; v1.x gets 6+ months security patches.

**Why it matters:** Install only what you need (smaller bundles), but existing v1 imports break. Run codemod before upgrading dependencies.

---

### **Claude Code MCP Workspace Trust Model**
[Documentation](https://code.claude.com/docs/en/mcp)

v2.1.196 introduces workspace trust: `.mcp.json` approvals require explicit workspace trust; cloned repos can't auto-approve servers unless user grants trust. `claude mcp list`/`get` no longer auto-spawn untrusted servers from committed `.claude/settings.json`. Pending approvals now marked with `⏸`.

**Why it matters:** Team-shared MCP configs won't auto-execute on clone; add explicit trust step to onboarding docs.

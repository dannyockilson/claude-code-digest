## 🚨 Breaking Changes & Action Required

### Claude Code v2.1.259 — Managed MCP & Headless Mode
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.259)

**Breaking:** `managedMcpServers` setting allows orgs to push HTTP/SSE MCP servers to all users (command-based entries are skipped). New `--permission-prompts none` flag auto-denies all prompts in headless/unattended sessions while respecting permission mode. Fixed concurrent session corruption that lost workspace trust and MCP state when running multiple sessions simultaneously. **Critical security fix:** Bash `Read()` deny rules now cover files in option values like `--ignore-revs-file=.env`, git operands, and compound commands.

**Why it matters:** Org-wide MCP deployments become viable, and the security fix closes a major sandbox escape vector for credentials in CLI flags.

---

### Claude Code v2.1.257 — Fable 5.1 Default + Containment Escape Rules
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.257)

Claude Fable 5.1 is now the default model (1M context, $0.25/Mtok cache reads). New **Containment Escape** rule blocks auto-approval of cloud metadata fetches and cross-tenant reach by default—requires env config to allow. Added session-only effort override (`/effort s`), time format settings (12/24-hour, UTC, strftime), and permission blocking for reads outside working directories. 50+ bug fixes including: Remote Control model selection ignored, background sessions losing stashed prompts, subagents stopping on dropped connections (now auto-continue), and symlink path traversal in plugins.

**Why it matters:** Fable 5.1's larger context and improved caching economics change cost profiles; containment rules prevent accidental cloud metadata leaks.

---

### MCP Configuration Now Requires Explicit `type` Field
[Docs: Claude Code MCP](https://code.claude.com/docs/en/mcp)

MCP configuration now requires explicit `type` field for HTTP/SSE/WebSocket servers (v2.1.219+)—missing type causes server to skip with clear error messaging. `CLAUDE_PROJECT_DIR` environment variable now available to stdio servers for stable project-root path resolution, with `roots/list` notifications when working directories change (v2.1.203+).

**Why it matters:** Silent misconfigurations are now caught early; project-root awareness fixes fragile relative-path assumptions in MCP servers.

---

### Agent SDK v0.3.261 — Plugin Delivery Breaking Fix
[Release Notes](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.261)

**Breaking fix:** `pluginDelivery: 'initialize'` now sends plugins via stdin instead of command line args, resolving Windows failures when plugin count exceeds CLI limits—impacts all multi-plugin agent deployments. Critical test fix: `query()` no longer throws "Object not disposable" in Node ≤22 vm contexts (Jest `node` env, vitest `vmThreads`/`vmForks`) and Node <18.18—fixes CI/test runner compatibility.

**Why it matters:** Windows multi-plugin workflows were silently broken; stdin delivery unblocks scaling plugin counts without hitting CLI length limits.

## 🆕 New Releases

### Claude Code v2.1.261 — Output Control + Skill Auditing
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.261)

Added `bashOutputMaxChars` and `taskOutputMaxChars` settings (up to 128K) to control inline command output before file spillover—critical for verbose CLI workflows. New `/skill-doctor` command audits unused loaded skills and their context cost, enabling cleanup of bloated configurations. Fixed critical input bug where typed/pasted characters drop or appear out-of-order during fast typing or key repeat. Added `--append-subagent-system-prompt-file` flag for large system prompts and improved `/status`/`claude doctor` org policy diagnostics.

**Why it matters:** Output settings prevent terminal spam from verbose commands; skill-doctor helps manage context budget as skill libraries grow.

---

### Claude Code v2.1.260 — Diff Panel + Caching Regression Fix
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.260)

Added `/diff` panel in fullscreen mode showing uncommitted changes as Claude edits—improves visibility into file modifications during coding sessions. Fixed critical Bash sandbox permission bug where paths with parentheses were incorrectly marked writable, plus added prompt-cache miss diagnostics to `/cost` output. **Fixed prompt caching regression on Fable 5.1** where context after tool results wasn't cached, causing re-transmission on every tool-call turn. Resolved 40+ workflow bugs including file permission tracking stale data, MCP server initialization timing, and agent team message loss during API retries.

**Why it matters:** Caching regression fix eliminates unexpected cost spikes on Fable 5.1; diff panel reduces "what changed?" context-switching.

### Claude Code v2.1.258 — macOS 12 Hotfix
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.258)

**CRITICAL:** Fixed macOS 12 (Monterey) launch failure regression from v2.1.255—restores functionality for older macOS users. Fixed remote/scheduled session failures when permission approvals are re-sent and can't be applied ("user messages must have non-empty content" error).

### Claude Code v2.1.252 — macOS Task Directory + Permission Persistence
[Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.252)

Fixed Bash command failures on macOS due to tasks directory handling—resolves "task output swap refused" errors that blocked workflows. Fixed "always allow" permissions not persisting in projects without existing `.claude/settings.local.json`, requiring manual re-approval each session. Fixed Remote Control session hangs (minutes-long stalls) when claude.ai connection degrades after tool completion. Fixed background task notifications with large failure output (e.g., git errors) exceeding API request limits and breaking conversations.

**Why it matters:** macOS workflows are unblocked; permission persistence fix reduces approval fatigue in new projects.

**Why it matters:** Hooks enable non-blocking workflows and environment-aware automation without custom agent modifications.
